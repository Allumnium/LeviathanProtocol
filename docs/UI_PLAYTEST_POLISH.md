# Playtest UI adjustments

The main tabs are **Fleet**, **Ships**, **Research**, **Map**. Fleet opens first; Ships replaces the visible Hangar name. Internal file/save names stay compatible.

In Fleet, drag on empty space to box-select ships, then drag a selected ship to move the group. Relative spacing is preserved, including at the formation boundary. A group move saves once, atomically. Middle-drag and the wheel still pan/zoom; neither moving nor selecting resets the camera. Click empty space to deselect. With no single ship selected, the right panel offers Repair All with the total credit cost. It repairs living ships and installed components together; failed saves restore both health and credits.

Selection uses a white glow sampled from each chassis silhouette. There are no green selection circles or floating Equip/Salvage buttons in the formation canvas. Single-click a ship in the Fleet roster to select it; double-click to open Ships fitting for that ship. Returning to Fleet preserves formation pan/zoom. Equipment and salvage remain available in the existing detail/editor panels. Salvage requires a small confirmation window; its shared top-right X cancels. The flagship remains protected.

Fleet, Ships and Map use stationary stars from the main menu's existing sprite animation and twinkle/click effects. Layouts are seeded from the persisted campaign seed and map-node ID using `set_area` / `area_seed`. A normalized pool of 220 stars makes generation independent of viewport size, resize history, UI rebuilding and panel layout; density selects a stable prefix. Reopening/Continue or returning to the same node recreates its stars; another node gets a distinct layout. Animation uses the application clock so refreshes do not reset twinkle phases. Battle scenery also uses the encounter node's seed. No new save fields are needed, and visual generation never consumes gameplay randomness. The shared canvas background is near-black, with no purple fill. Menu flight behavior is unchanged. Reduced motion is no longer a setting or runtime mode.

Travel now visibly flies the flagship between map nodes at a steady speed during each leg. Distance controls the presentation duration, bounded to 2-3 seconds. Departure is saved once before the animation; other departures/tab changes are blocked until the flight finishes. Arrival then opens the encounter or refreshes the destination. Existing research/trade timing and recovery rules remain unchanged.

The header uses `assets/science.png` for RP. Mini Turret uses the supplied `assets/miniTurret.png` in stock, the drag preview, and fitted rendering. Catalog `art_mount: [62, 65, 82]` identifies the circular base center and diameter in source pixels. That circle is centered/scaled to the mount rather than centering the whole image, which includes the protruding barrel. Shared rendering applies this in Ships, Fleet and battle. No source PNG was changed.

Validation: `tests/test_ui_polish.gd` exercises actual viewport box/group mouse drags, pan/zoom preservation, saved formation positions, empty-space deselection, Repair All and failed-save rollback, salvage cancellation/confirmation, turret geometry, stationary clickable stars, and actual travel/duplicate-departure prevention. Native captures are under `.local/ui-polish/`. The baseline runner includes the suite and runs it again with native rendering under `-Native`. Existing ship fitting/layout checks explicitly open Ships now that Fleet is the default tab.

Result: all 14 baseline suites passed, including 299 screen/layout checks and 39 focused polish checks in both headless and native runs. The existing native equipment drag suite also passed all 115 checks. Resource-reference and whitespace checks passed. Godot's existing Windows certificate-store and renderer shutdown diagnostics remain unrelated to these changes.
